# 转录渲染规范

对话窗口是这个应用的正面。一次长任务会往里写进几百条消息、上千次工具调用，读起来是否顺畅，
比任何一个功能都更决定它像不像一个成熟产品。这份文档记下已经定下来的规则和它们的理由——
不是风格偏好，每一条都对应过一次实际的难看。

---

## 一、什么聚合，什么不聚合

**所有工具执行都是一行。** 一个文件和九个文件长得一样。

这是最重要的一条。此前的做法是"不到三个画卡片，够三个折成一行"，于是同一种工作的外观取决于
模型这一次恰好批了几个调用，读的人每隔几段就要重新认一次眼前是什么。阈值已经删掉。

**一行说的是做了什么，不是做了几件。**

| 情况 | 显示 |
| --- | --- |
| 一个动作，有名字可说 | `创建文件 main.css` |
| 一个动作，没有名字 | `执行命令` |
| 同类多个 | `创建文件 3 个` |
| 多类混合 | `执行命令 3 个、修改文件 3 个` |
| 整段有增删 | 行尾接 `+932 -0` |

`执行了 4 个操作` 数的是没人看见的事件；`创建文件 2 个、执行命令 3 个` 是同一排卡片，读出来。

**什么会打断一串：**

- 模型说的话（正文文字）——那是它在跟你讲话，不该被吞进摘要，也不该被跨过去
- 一次上下文压缩

**什么不会打断：**

- 思考过程（默认折起，不是对你说的）
- 工具结果消息——它不是转录里的条目，是那张卡片的内容。**曾经因为把它当成普通消息，每两次
  调用之间都插着一条"别的东西"，一串七个进来变成七串各一个，成组永远不会发生。**

---

## 二、不跳动

一次回复到达要花几分钟，期间转录不该在读的人眼前上下弹。已知的位移源和处理：

**正在流式的那条消息不参与分组。** 它的形状还在变——先来文字后来调用，或者反过来——分组要看
形状，于是每来一段增量它就在"并入上一串"和"自成一段"之间反复横跳，底下所有行跟着重建、重新
测量。它只在这一轮结束、形状定下来之后才并入。

**运行指示器整轮常驻。** 它曾经只在最后一条消息结束时出现，于是每次工具调用它都来一次又走一次，
46px 跟着来回，整轮都在动。一轮要么在跑要么不在，指示器说的就是这个。

**key 用内容的 id，不用数组下标。** 上方插入任何东西都不该让 React 把整段拆了重建。

**摘要行单行截断。** 文案变长不该把一行变成两行。

**展开的高度是量出来的。** `height: auto` 不能过渡；退而求其次的 max-height 猜测要么截断长列表、
要么大半段时间在铺空气，动画提前跑完然后戛然而止。列表始终挂载，用 `ResizeObserver` 量真高度。

---

## 三、间距

一套刻度，靠得近的表示属于彼此：

**转录里的一切，间距都是 10px（`mb-2.5`）。** 正文、思考行、工具摘要行、用户气泡、运行指示器、
恢复行、压缩分隔线——没有例外。

先试过按层次分档（属于彼此的 6px，段落之间 14px），意图是让归属看得出来。实际读下来是另一回事：
行与行之间的距离一会儿宽一会儿窄，整页显得没有秩序，而"哪一行属于哪一段"本来就靠文案和缩进说清
楚了，不必再用间距讲一遍。一个值，到处一样。

回复下方的时间戳行常驻占位（18px），这样指针划过转录时不会让内容跳动——它是间距之外唯一的固定
留白，已经压到控件允许的最矮。

## 四、进行中的样子

**转动的弧**（`Spinner`）是唯一表示"在跑"的动画，应用里到处用的是同一个：工具卡、聚合行、清单里
进行中的那一步、侧栏里正在执行的会话。

**进度光带**（`dw-rail`）在卡片底部横过。它是一条整宽渐变在平移——不是分别动 `left` 和 `right`，
那样中点处会撑到近一半再缩回去，读起来是呼吸而不是移动，而且每轮末尾在右边消失、又从左边冒出来，
接缝清清楚楚。匀速，因为从眼前经过的东西不会在窗口边缘减速。

**扫光**（`dw-glide`）用在正在执行的那一行摘要上，代替 spinner——一行既在动又带转圈，是同一件事
说了两遍。

方向很关键。第一版让文字本身成为渐变并淡到透明，于是词句只在光带掠过的一瞬可见，其余时间是一行
读不出来的闪烁。错在方向：那道光把文字推向背景色。现在文字始终是自己的颜色，光带经过时只让那一段
**更深**——任何时刻都读得清，动的是强调而不是存在。

两个动画不能挂在同一个元素上：`animation` 是单一属性，后一个类替换前一个而不是叠加。入场动画在外层，
扫光在里层的文字上。

**思考文案**由本地预设，不问模型。见 `thinking-words.ts`：按最近一次未完成的调用挑一组词
（Reading up / Drafting / Letting it rip / Rummaging / Proving it…），每 4.2 秒换一个，超过 45 秒
换成 Still at it、This one's stubborn 这类。用 tick 而不是随机数，所以重绘不会换词，只有时间会。

英文，因为它紧挨着 `42s · 63.6k tokens`——中文短语出现在那一行里像另一个声音打断了技术读数。

## 五、运行时说的话，不画成人说的话

自动继续、压缩摘要这些是运行时注入给模型的消息。它们必须是 user 角色（模型只认这个角色的指令），
但窗口不能画成用户气泡——**画成气泡就是让转录显示用户问了他从没问过的话**。

- 自动继续 → **完全不显示**。曾经画过一行「自动继续 · 清单尚未完成」来解释这一轮为什么又开始，
  但它两侧的工作是连续的一段，一条横线穿过中间，打断的是从未停下的东西。剩下多少，清单已经在说。
- 被自动继续接上的那一轮，**不显示时间戳**。数据上它确实结束了（模型只说话没调工具），可读的人
  看到的是一段连着的工作，中间冒出一个时刻，像是有谁在那里插了一句。时间戳属于真正的结尾。
- 压缩摘要 → 不显示（是记账，不是内容）
- 压缩发生处 → 一条分隔线「以上内容已压缩为摘要」，在**发生的位置**，不在末尾。这一条留着，因为
  它之后模型据以工作的东西真的变了——那是内容的分界，不是机械的分界。

按内容识别而不只是靠标记：标记是后加的，此前写进日志的那些没有。

## 六、长对话的性能

**每张卡片只订阅自己那条记录。** 工具输出是流式的，一次安装每秒发几十次更新，每次替换整张
`toolRuns` 表；读这张表的组件全都重绘。转录顶层曾经读着它，于是每一小段输出都重绘全部消息。

**聚合行只订阅标量。** 选择器返回对象每次都是新的、永远看着像变了；返回数字和字符串按值比较。

**只挂载最近一段。** 一天的会话有几千条消息，各带卡片和展开器。全挂上去的内存不会还回来，每次
重绘都要走一遍整棵树。更早的按需展开。同一段 600 条消息的对话，DOM 节点从 6547 降到 1443。

## 七、上下文压缩的显示

压缩是一件应该被看见的事——它之后模型据以工作的是摘要，而不是原话。

- 事件写进会话日志（唯一被持久化的事件类型），所以重开会话仍看得到
- 转录里在发生的位置画一条分隔线
