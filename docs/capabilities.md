# 内置能力

设置界面里每一页对应的机制说明。界面只留操作，原理在这里。

---

## 浏览器

Agent 可以驱动一个真实的浏览器内核（离屏 `BrowserWindow`），看到的是脚本执行之后、
人眼所见的页面。`web_fetch` 只能拿到服务端返回的 HTML，对客户端渲染的页面是一具
空壳。

### 安全边界

- 页面内容始终当作**不可信数据**处理——里面的文字不会被当成指令执行，返回内容包在
  `<page>` 标签里明确标注来源。
- 每个会话一个独立的浏览器实例，随会话一起销毁。开启了沙箱与上下文隔离，触碰不到
  应用自身的 IPC。
- 首次访问一个站点走批准流程，与执行命令、写文件同一套权限。
- 只允许 `http` / `https`。

---

## 索引库

索引记录函数、类、接口、类型和常量的**定义位置**，Agent 用 `symbol` 工具查它。

和 grep 的区别：grep 一个常用函数名会返回所有调用点，索引只返回定义它的那一行。

索引按工作区构建，随文件改动增量更新。仓库很大时首次构建需要一点时间，构建期间
`symbol` 会退回到 grep。

## 钩子

在工具调用前后运行一段命令。

### 传参

| 方式 | 内容 |
| --- | --- |
| `$DW_TOOL` | 工具名 |
| `$DW_ARGS` | 参数（JSON 字符串） |
| stdin | 同样的信息，完整 JSON |

### 调用前与调用后

- **调用前 + 可阻断**：命令退出码非零时，这次调用会变成一条错误结果交给模型，而不是
  直接执行。可以用来保护特定文件、拦截危险命令。模型会看到 stderr 的内容——所以拦截
  时应该在 stderr 里写清楚原因，让它知道该怎么改。
- **调用后**：stdout 会附加到模型看到的结果里，可以用来做审计、自动格式化。

钩子自身跑不起来（命令不存在、工作目录缺失）与钩子判定阻断是分开报告的——否则一个
配置错误会伪装成安全策略拒绝，让人往错误的方向排查。

### 常见用途

- 审计所有命令
- 阻止改动受保护的文件
- 写入后自动格式化

## 移动端同步

桌面端是唯一的数据源——文件、终端和 MCP 进程都在这里。手机连上以后重放同一份会话
日志，可以查看正在进行的回合、批准操作、继续追问。两端看到的内容完全一致。

仅在本机所在局域网监听，需要配对令牌才能访问。
